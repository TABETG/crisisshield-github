# README: Classe `MfaController`

Ce fichier explique le rôle et l'utilité de la classe `MfaController.java`.

---

## 🇫🇷 Français

### 👔 Explication Professionnelle

`MfaController` est un contrôleur REST (`@RestController`) dédié à la gestion des opérations liées à l'authentification multi-facteurs (MFA) basée sur TOTP. Il expose une série de points de terminaison sécurisés qui permettent aux utilisateurs de configurer, activer, désactiver et vérifier leur MFA.

**Points de terminaison clés :**

-   **`POST /api/mfa/setup`** : Permet à un utilisateur authentifié d'initier la configuration du MFA. Le serveur génère un secret TOTP, le stocke temporairement pour l'utilisateur, et renvoie le secret ainsi qu'une URI de QR code. L'utilisateur scanne ce QR code avec son application d'authentification.
-   **`POST /api/mfa/enable`** : Permet à un utilisateur authentifié d'activer le MFA. L'utilisateur doit fournir le secret TOTP qu'il a reçu lors de la configuration et un code TOTP généré par son application. Le serveur vérifie la validité du code avant d'activer le MFA.
-   **`POST /api/mfa/disable`** : Permet à un utilisateur authentifié de désactiver le MFA. Pour des raisons de sécurité, l'utilisateur doit fournir un code TOTP valide pour confirmer la désactivation.
-   **`POST /api/mfa/verify`** : Permet de vérifier un code TOTP. Ce point de terminaison peut être utilisé pour des tests ou pour des vérifications ponctuelles.

Ce contrôleur interagit avec le `UserService` pour toutes les logiques métier liées au MFA, garantissant une séparation claire des préoccupations.

### 🧒 Explication pour un enfant

Imagine que `MfaController` est le "guichet spécial" du château pour ta super serrure.
-   Si tu veux installer une super serrure, tu vas au guichet `/setup`, et on te donne un secret et un dessin magique (QR code).
-   Quand tu as scanné le dessin et que ton téléphone est prêt, tu vas au guichet `/enable` avec ton secret et un code de ton téléphone pour activer la super serrure.
-   Si tu ne veux plus de la super serrure, tu vas au guichet `/disable` avec un code de ton téléphone pour la retirer.
-   Et si tu veux juste vérifier si un code de ton téléphone est bon, tu vas au guichet `/verify`.

Le guichetier (`MfaController`) s'assure que tout est fait correctement et en toute sécurité.

## 🇬🇧 English

### 👔 Professional Explanation

`MfaController` is a REST controller (`@RestController`) dedicated to managing operations related to TOTP-based Multi-Factor Authentication (MFA). It exposes a series of secure endpoints that allow users to set up, enable, disable, and verify their MFA.

**Key Endpoints:**

-   **`POST /api/mfa/setup`**: Allows an authenticated user to initiate MFA setup. The server generates a TOTP secret, temporarily stores it for the user, and returns the secret along with a QR code URI. The user scans this QR code with their authenticator app.
-   **`POST /api/mfa/enable`**: Allows an authenticated user to enable MFA. The user must provide the TOTP secret received during setup and a TOTP code generated by their app. The server verifies the code's validity before enabling MFA.
-   **`POST /api/mfa/disable`**: Allows an authenticated user to disable MFA. For security reasons, the user must provide a valid TOTP code to confirm deactivation.
-   **`POST /api/mfa/verify`**: Allows verification of a TOTP code. This endpoint can be used for testing or one-time verifications.

This controller interacts with the `UserService` for all MFA-related business logic, ensuring a clear separation of concerns.

### 🧒 Kid's Explanation

Imagine `MfaController` is the "special counter" at the castle for your super lock.
-   If you want to install a super lock, you go to the `/setup` counter, and they give you a secret and a magic drawing (QR code).
-   When you've scanned the drawing and your phone is ready, you go to the `/enable` counter with your secret and a code from your phone to activate the super lock.
-   If you no longer want the super lock, you go to the `/disable` counter with a code from your phone to remove it.
-   And if you just want to check if a code from your phone is correct, you go to the `/verify` counter.

The counter clerk (`MfaController`) makes sure everything is done correctly and securely.

## 🇸🇦 العربية

### 👔 شرح احترافي

`MfaController` هو متحكم REST (`@RestController`) مخصص لإدارة العمليات المتعلقة بالمصادقة متعددة العوامل (MFA) المستندة إلى TOTP. يكشف عن سلسلة من نقاط النهاية الآمنة التي تسمح للمستخدمين بإعداد وتفعيل وتعطيل والتحقق من MFA الخاص بهم.

**نقاط النهاية الرئيسية:**

-   **`POST /api/mfa/setup`**: يسمح للمستخدم المصادق عليه ببدء إعداد MFA. يقوم الخادم بإنشاء سر TOTP، ويخزنه مؤقتًا للمستخدم، ويعيد السر بالإضافة إلى معرف موارد موحد لرمز الاستجابة السريعة (QR code URI). يقوم المستخدم بمسح رمز الاستجابة السريعة هذا باستخدام تطبيق المصادقة الخاص به.
-   **`POST /api/mfa/enable`**: يسمح للمستخدم المصادق عليه بتفعيل MFA. يجب على المستخدم تقديم سر TOTP الذي تلقاه أثناء الإعداد ورمز TOTP الذي تم إنشاؤه بواسطة تطبيقه. يتحقق الخادم من صحة الرمز قبل تفعيل MFA.
-   **`POST /api/mfa/disable`**: يسمح للمستخدم المصادق عليه بتعطيل MFA. لأسباب أمنية، يجب على المستخدم تقديم رمز TOTP صالح لتأكيد التعطيل.
-   **`POST /api/mfa/verify`**: يسمح بالتحقق من رمز TOTP. يمكن استخدام نقطة النهاية هذه للاختبار أو للتحقق لمرة واحدة.

يتفاعل هذا المتحكم مع `UserService` لجميع منطق الأعمال المتعلق بـ MFA، مما يضمن فصلًا واضحًا للاهتمامات.

### 🧒 شرح لطفل

تخيل أن `MfaController` هو "النافذة الخاصة" في القلعة لقفل الفائق الخاص بك.
-   إذا كنت ترغب في تثبيت قفل فائق، تذهب إلى نافذة `/setup`، ويعطونك سرًا ورسمًا سحريًا (رمز QR).
-   عندما تقوم بمسح الرسم وهاتفك جاهز، تذهب إلى نافذة `/enable` بسرك ورمز من هاتفك لتفعيل القفل الفائق.
-   إذا لم تعد ترغب في القفل الفائق، تذهب إلى نافذة `/disable` برمز من هاتفك لإزالته.
-   وإذا كنت ترغب فقط في التحقق مما إذا كان الرمز من هاتفك صحيحًا، تذهب إلى نافذة `/verify`.

يتأكد موظف النافذة (`MfaController`) من أن كل شيء يتم بشكل صحيح وآمن.
